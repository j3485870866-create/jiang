# 手机端作品集二维拖动设计

## 目标

让手机端作品集中央图形支持上、下、左、右及斜向拖动，消除纵向手势被取消后产生的卡顿感。

## 根因

当前手势状态机会在移动超过 `6px` 后区分横向和纵向：

- 横向手势进入拖动状态并转发给 WebGL 画布。
- 纵向手势进入取消状态，不再转发后续移动。

中央拖动区已经使用 `touch-action: none`，因此纵向手势既不会控制画廊，也不会滚动网页，表现为“卡住”。

## 已确认的交互

- 仅手机端中央圆形区域接管画廊拖动。
- 手势从中央区域开始，累计位移超过 `6px` 后进入拖动。
- 不再判断横向或纵向；任意方向都进入同一个 `dragging` 状态。
- 每次移动的完整 `clientX` 和 `clientY` 坐标都转发给原 WebGL 画布。
- 拖动开始后，手指移出中央区域仍持续控制画廊。
- 松手或触摸取消后结束拖动，下一次必须重新从中央区域开始。
- 中央区域内不滚动网页；从中央区域外开始的手势保持正常网页滚动。
- `64%` 中央区域尺寸和 `6px` 防误触阈值保持不变。
- 桌面端行为保持不变。

## 实现

### 共享手势模块

将 `createMobileDragDecision` 的状态简化为：

- `pending`：尚未超过 `6px` 阈值。
- `dragging`：超过阈值后，无论方向都保持拖动，直至结束。

安装器只判断 `pending` 与 `dragging`，不再提前返回纵向手势。

### 独立页面

`Jiang-Hao-个人网站.html` 的内联手势逻辑同步取消方向判断，保证本地单页与 Vite 部署版本一致。

## 验证

- 小于 `6px` 的位移保持 `pending`。
- 横向、纵向和斜向位移超过阈值后均进入 `dragging`。
- 纵向拖动事件完整转发给画布。
- 任意方向拖动结束后正确发送 `pointerup` 并重置。
- 手机视口实测中央纵向拖动画廊时页面 `scrollY` 不变。
- 手机视口实测区域外仍可滚动网页。
- 桌面端透明拖动层继续隐藏。

## 非目标

- 不修改中央区域大小、图片、标题、文字或 WebGL 渲染。
- 不移除 `6px` 防误触阈值。
- 不允许从中央区域内滚动网页。
