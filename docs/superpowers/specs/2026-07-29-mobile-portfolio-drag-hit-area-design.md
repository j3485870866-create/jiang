# 手机端作品集拖动命中区域设计

## 目标

解决手机浏览作品集页面时，整块球形画廊持续接管触摸事件、导致页面难以继续向下滚动的问题，同时保留作品画廊的拖动交互。

## 交互规则

- 本次调整只影响宽度不超过 `760px` 的手机端，桌面端保持现有全画布拖动交互。
- 手机端只有从当前画廊中心圆形附近按下时，才允许启动作品拖动。
- 可启动区域以画廊中心为圆心，以当前主圆形半径的 `112%` 为命中半径，即在可见圆形外额外扩张 `12%`。
- 一旦拖动成功启动，手指可以继续移动到画廊或页面的其他区域，拖动不会因为离开命中圆而中断。
- `pointerup` 或 `pointercancel` 后立即结束本次拖动并释放指针捕获。
- 下一次拖动必须重新从中心命中圆内开始。
- 命中圆以外的触摸不启动画廊拖动；上下滑动由浏览器正常滚动页面。
- 即使触摸从命中圆内开始，明显的纵向手势仍优先作为页面滚动，横向手势才启动作品拖动。

## 实现边界

- 不新增可见按钮、边框或命中区域提示。
- 不修改作品图片、标题、小标题、圆片尺寸、动画速度或桌面排版。
- 不改变现有作品数据与选中作品的更新逻辑。
- 触摸区域根据画廊实际显示尺寸动态计算，避免依赖某一种手机分辨率。

## 事件流程

1. 手机端收到 `pointerdown`。
2. 根据指针坐标和画廊中心计算距离。
3. 若起点位于 `112%` 命中圆之外，不进入拖动候选状态。
4. 若起点位于命中圆内，记录起点，但暂不阻止页面滚动。
5. 移动超过小阈值后判断方向：
   - 纵向位移更大：取消候选状态，交给浏览器滚动。
   - 横向位移更大：进入画廊拖动状态，并捕获该指针。
6. 拖动状态持续到 `pointerup` 或 `pointercancel`，之后清空状态。

## 验证标准

- 从中心圆外上下滑动，页面可以连续滚动。
- 从中心圆内纵向滑动，页面仍然可以滚动。
- 从中心圆及其外扩 `12%` 范围内横向拖动，可以控制作品画廊。
- 拖动开始后，手指移动到中心区域之外仍能继续控制画廊。
- 松手后从区域外再次滑动不会控制画廊。
- 桌面端鼠标拖动行为无变化。
- 现有构建与完整性测试继续通过。
