# 手机端作品集拖动流畅度修复设计

## 目标

解决手机端作品集画廊起拖迟缓、横向拖动时偶尔带动网页纵向滚动的问题，同时适度扩大可拖动区域。

## 已确认的交互

- 仅手机端生效，桌面端保持现状。
- 中央圆形拖动区直径由画廊短边的 `56%` 扩大到 `64%`。
- 起拖判断阈值由 `12px` 降为 `6px`，减少拖动开始前的停顿感。
- 中央拖动区专门用于操作画廊，设置 `touch-action: none`，不再触发网页滚动。
- 页面纵向滚动需要从中央拖动区之外开始。
- 手势必须从中央拖动区内开始；拖动开始后，即使手指移出该区域也继续控制画廊。
- 松手或触摸取消后结束本次拖动；下一次仍必须从中央区域重新开始。
- 中央区域内以纵向为主的手势不旋转画廊，也不滚动页面。

## 实现边界

### 样式

- 将手机端透明拖动层尺寸改为 `min(64vw, 64vh)`。
- 将透明拖动层的 `touch-action` 改为 `none`。
- 作品集 WebGL 画布继续禁用直接指针事件，由透明拖动层统一接收手机手势。

### 手势逻辑

- `diameterRatio` 默认值改为 `0.64`。
- `threshold` 默认值改为 `6`。
- 继续使用横纵方向判断，避免纯纵向手势误转动画廊。
- 横向手势锁定后继续使用指针捕获，将后续移动和结束事件转发到原画布。

### 独立页面一致性

Vite 页面与 `Jiang-Hao-个人网站.html` 使用相同的尺寸、阈值和触摸策略，避免本地预览与部署版本表现不同。

## 验证

- 单元测试覆盖 `64%` 命中范围和 `6px` 起拖阈值。
- 集成测试覆盖中央横向手势、区域外起拖无效、松手重置。
- HTML 完整性测试覆盖 `touch-action: none` 及 Vite/独立页面一致性。
- 手机视口浏览器验证：
  - 中央横向拖动立即响应。
  - 横向拖动不改变页面滚动位置。
  - 中央区域外仍可上下滚动页面。
  - 桌面端交互保持不变。

## 非目标

- 不修改作品集图片、标题、文案或 WebGL 动画。
- 不改变桌面端拖动方式。
- 不为中央区域保留纵向页面滚动。
