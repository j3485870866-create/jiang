# 手机端交互动效与性能预算设计

## 目标

在不复制桌面端高负载效果的前提下，让手机端获得明确、跟手的触摸反馈，并避免离屏 CSS 动画继续消耗渲染资源。现有卡片翻页、作品集二维拖动、滚动入场和留言弹窗行为必须保持不变。

## 采用方案

采用“CSS + 触摸反馈 + 视口感知”的平衡方案：

- 可点击卡片和按钮在触摸按下时显示短暂的白绿色轮廓光，松手或取消触摸后立即恢复。
- 使用统一的手机端动效控制器标记当前可见区块；离屏区块的 CSS 动画暂停。
- 页面进入后台时暂停所有受控 CSS 动画，返回前台后恢复当前可见区块。
- `prefers-reduced-motion: reduce` 开启时不安装增强交互，保留静态内容。
- 手机端模糊文字 Canvas 的像素比上限从 2 降为 1.5，并以 30 FPS 渲染；桌面端保持原有 60 FPS 与 2 倍像素比。

## 架构

新增 `src/mobileMotionBudget.js`，只负责三件事：

1. 通过媒体查询决定是否启用手机端增强。
2. 通过 `IntersectionObserver` 给可见区块添加 `data-mobile-motion-active`。
3. 通过事件代理给声明了 `data-mobile-interactive` 的元素添加和清理按压状态。

`src/main.jsx` 负责选择需要增强的既有元素并安装控制器。视觉规则继续放在 `index.html` 的手机端样式中，不重构既有大型页面文件。

## 性能约束

- 不新增持续运行的 `requestAnimationFrame` 循环。
- 不新增粒子系统、WebGL 场景或大面积实时模糊。
- 按压反馈只使用轮廓、透明度和短时阴影，不触发布局计算。
- `IntersectionObserver` 阈值为 0.08，让动画在进入屏幕边缘时恢复。
- 页面不可见时受控动画必须暂停。
- Canvas 在手机端使用最高 1.5 DPR、30 FPS。

## 交互范围

增强以下元素：

- 性格卡片；
- 目标卡片；
- “正在学习”和“未来目标”卡片；
- 联系方式、二维码、发送留言及弹窗内操作按钮。

不把按压光效直接加在“关于我”可拖拽照片和作品集拖动区域上，避免与现有手势的 transform、pointer capture 和 touch-action 发生冲突。

## 降级与清理

- 浏览器不支持 `IntersectionObserver` 时，所有区块视为活动状态。
- 切换到桌面宽度或减少动态效果时，移除根级状态、区块状态和事件监听。
- 安装函数返回清理函数，方便热更新和测试。

## 验证

- 单元测试覆盖启用条件、视口状态、按压状态和清理行为。
- 现有 14 项回归测试继续通过。
- Vite 生产构建必须成功。
- 手机视口手动确认按压反馈出现、滚动不被阻断、作品集拖动和照片翻页不受影响。
